Saya ingin kamu membangun aplikasi MVP bernama `identity-monitor-agent`, yaitu agent lokal berbasis Go yang berjalan di satu laptop khusus untuk memantau penyebutan nama dan penggunaan foto seseorang pada halaman web publik.

Aplikasi harus benar-benar runnable, bukan hanya membuat rancangan, pseudocode, atau dokumentasi. Kerjakan end-to-end sampai build, test, dan demonstrasi lokal berhasil.

## Tujuan aplikasi

Agent berjalan terjadwal dari pukul 08.00 sampai 17.00 WIB dan melakukan:

1. Membuka browser lokal.
2. Menggunakan browser profile khusus yang dapat menyimpan sesi login.
3. Menjalankan daftar pencarian nama, alias, jabatan, dan kata kunci.
4. Membaca hasil pencarian publik.
5. Mengambil teks, URL, nama akun, tanggal, engagement jika tersedia, dan screenshot.
6. Melakukan deduplikasi.
7. Menganalisis relevansi, sentimen, dan risiko menggunakan Ollama lokal.
8. Menyimpan hasil ke SQLite.
9. Menampilkan hasil pada dashboard lokal.
10. Menghasilkan laporan harian dalam format JSON dan CSV.

Aplikasi tidak boleh mengirim report, pesan, atau permintaan takedown secara otomatis. Aplikasi hanya membuat kasus dan menunggu persetujuan manusia.

## Batasan penting

Aplikasi hanya boleh mengakses halaman publik atau halaman yang memang dapat diakses oleh akun monitoring yang sah.

Jangan membuat mekanisme untuk:

- Melewati CAPTCHA.
- Menghindari rate limit secara manipulatif.
- Mengubah fingerprint browser.
- Menggunakan proxy rotation untuk menghindari pemblokiran.
- Mengakses akun private tanpa izin.
- Membaca password manager.
- Mengambil OTP secara otomatis.
- Mengubah email, password, atau keamanan akun.
- Mengirim report/takedown otomatis.
- Mengunduh atau menjalankan file asing.
- Melakukan engagement otomatis seperti like, comment, follow, atau share.

Jika ditemukan CAPTCHA, MFA, login ulang, atau halaman verifikasi, hentikan job dengan status `HUMAN_ACTION_REQUIRED`.

## Tech stack wajib

Gunakan:

- Go 1.25.
- `chromedp` untuk mengendalikan Chrome/Chromium melalui Chrome DevTools Protocol.
- Fiber untuk local API dan dashboard.
- SQLite menggunakan driver pure Go tanpa CGO.
- Ollama melalui local HTTP API.
- YAML untuk konfigurasi subjek dan sumber.
- `robfig/cron` atau scheduler Go yang setara.
- Prometheus client untuk metrics.
- `testify` untuk unit test.
- `golangci-lint`.
- Gunakan kodingan clean architecture, clean code, hindari duplicate function, pisahkan struct sesuai kebutuhan jangan disatukan di controller
- Docker Compose hanya untuk service pendukung yang memang dibutuhkan.
- HTML, CSS, dan JavaScript sederhana yang di-embed ke binary Go untuk dashboard lokal. Gunakan metronic_html_v8.2.3_demo2 sebagai template html nya, untuk dashboard pake social.html disesuaikan dengan kebutuhan aja

Jangan menggunakan cloud LLM atau API media sosial.

Semua analisis AI harus menggunakan Ollama lokal. Nama model harus configurable melalui environment variable dan file konfigurasi, jangan di-hardcode.

## Komponen utama

### 1. Collector supervisor

Buat supervisor Go yang bertanggung jawab terhadap:

- Menjalankan scheduler.
- Membuat collection run.
- Menentukan subject dan keyword yang akan diproses.
- Menjalankan source adapter satu per satu.
- Membatasi concurrency.
- Menerapkan timeout.
- Menyimpan progress.
- Melanjutkan job yang gagal atau tertunda.
- Menghentikan pekerjaan setelah pukul 17.00 WIB.
- Mengirim heartbeat.
- Menangani graceful shutdown.
- Mencegah dua job identik berjalan bersamaan.

Setiap run harus mempunyai:

```text
run_id
subject_id
source
query
started_at
finished_at
status
total_discovered
total_stored
total_duplicate
total_failed
error_message
```

Gunakan state berikut:

```text
PENDING
RUNNING
COMPLETED
FAILED
PAUSED
HUMAN_ACTION_REQUIRED
CANCELLED
```

### 2. Browser manager

Buat browser manager menggunakan `chromedp`.

Persyaratan:

- Dapat menggunakan Chrome/Chromium yang terinstal di komputer.
- Menggunakan persistent user data directory khusus aplikasi.
- Setiap source mempunyai browser profile terpisah.
- Browser dapat berjalan dalam mode headful dan headless.
- Headful menjadi default untuk fase MVP.
- Mendukung screenshot.
- Mendukung page timeout.
- Mendeteksi redirect ke login page.
- Mendeteksi indikasi CAPTCHA atau verification challenge.
- Tidak boleh mencoba melewati CAPTCHA.
- Menyimpan diagnostic screenshot ketika terjadi error.
- Browser profile dan cookie tidak boleh masuk Git.

Tambahkan command:

```bash
identity-monitor-agent browser bootstrap --source=<source>
```

Command tersebut membuka browser headful agar operator dapat login manual. Setelah operator selesai login, profile browser dipakai oleh job berikutnya.

### 3. Source adapter

Buat interface:

```go
type SourceAdapter interface {
    Name() string
    Search(ctx context.Context, task SearchTask) ([]RawMention, error)
    CheckSession(ctx context.Context) SessionStatus
}
```

Untuk MVP, implementasikan:

1. `generic_web_search`
2. `youtube_public_search`

Jangan membuat selector tersebar di banyak file. Simpan selector dan aturan ekstraksi per source dalam satu adapter yang jelas.

Setiap adapter harus mendukung:

- Query.
- Maximum result.
- Maximum scroll.
- Delay wajar antartindakan.
- Timeout.
- Screenshot saat menemukan high-risk candidate.
- Penanganan halaman kosong.
- Penanganan layout berubah.
- Penanganan session expired.
- Fixture HTML untuk unit/integration test agar test tidak bergantung pada situs asli.

Jangan melakukan scraping agresif. Gunakan limit konservatif dan jadikan semuanya configurable.

### 4. Keyword generator

Untuk setiap subjek, buat kombinasi query dari:

- Nama lengkap.
- Nama populer.
- Alias.
- Jabatan.
- Instansi.
- Username resmi.
- Kata kunci risiko.
- Variasi ejaan yang diberikan dalam konfigurasi.

Contoh:

```text
"Nama Lengkap"
"Nama Lengkap" "Jabatan"
"Nama Lengkap" "Instansi"
"Nama Lengkap" penipuan
"Nama Lengkap" akun palsu

```

Jangan membuat variasi ejaan secara liar. Gunakan hanya alias yang dikonfigurasi dan variasi aman yang deterministik.

### 5. Extractor

Setiap hasil pencarian minimal menghasilkan:

```go
type RawMention struct {
    Source          string
    SourceURL       string
    AuthorName      string
    AuthorHandle    string
    ContentText     string
    PublishedAt     *time.Time
    CollectedAt     time.Time
    Engagement      map[string]int64
    MediaURLs       []string
    ScreenshotPath  string
    RawMetadata     map[string]any
}
```

Normalisasikan:

- URL.
- Whitespace.
- Username.
- Waktu.
- Teks.
- Source identifier.

Buat content hash untuk deduplikasi.

Deduplikasi berdasarkan kombinasi:

- Canonical URL.
- Source identifier.
- Normalized content hash.
- Media perceptual hash jika tersedia.

### 6. Agentic fallback

Buat agent loop lokal yang menggunakan Ollama.

Agent tidak boleh mendapat akses shell atau filesystem secara bebas. Agent hanya boleh memilih tool dari allowlist:

```text
navigate
type_text
click_element
scroll_page
extract_visible_content
capture_screenshot
go_back
wait
finish
request_human
```

Setiap tool harus memiliki JSON schema yang ketat.

Batasi:

- Maksimal 20 langkah per task.
- Maksimal durasi per task.
- Maksimal scroll.
- Maksimal navigasi lintas domain.
- Hanya domain allowlist.
- Tidak boleh mengirim form.
- Tidak boleh mengunggah file.
- Tidak boleh menekan tombol report.
- Tidak boleh melakukan login otomatis.
- Tidak boleh membuka halaman account security.

Agentic fallback hanya dijalankan jika extractor deterministik gagal atau confidence hasilnya rendah.

Simpan setiap langkah agent ke audit log:

```text
step_number
observed_url
proposed_action
action_arguments
guardrail_result
execution_result
created_at
```

Jika action tidak diizinkan, tolak action tersebut dan akhiri task dengan status yang sesuai.

Konfigurasi:

Client harus mendukung:

- Health check.
- Chat completion.
- Structured JSON output.
- Timeout.
- Retry terbatas.
- Validasi response.
- Logging tanpa membocorkan data sensitif.
- Mock untuk unit test.

Jangan mengasumsikan model tertentu sudah terinstal. Saat startup, periksa model yang dikonfigurasi dan berikan pesan error yang jelas jika belum tersedia.

### 8. AI analysis

Setiap mention dianalisis menjadi:

```go
type AnalysisResult struct {
    Relevant          bool
    IdentityConfidence float64
    Sentiment         string
    SentimentScore    float64
    RiskCategory      string
    RiskScore         int
    ViolationCandidate bool
    Summary           string
    Reasons           []string
    RequiresReview    bool
    ModelName         string
    AnalyzedAt        time.Time
}
```

Nilai sentiment:

```text
positive
neutral
negative
unknown
```

Nilai risk category:

```text
normal_mention
criticism
misinformation
possible_impersonation
possible_scam
possible_doxxing
possible_threat
possible_manipulated_media
unknown
```

Aturan penting:

- Sentimen negatif tidak otomatis menjadi violation candidate.
- Kritik kebijakan tidak otomatis menjadi violation candidate.
- `ViolationCandidate` hanya kandidat untuk human review.
- AI tidak boleh mengambil keputusan takedown.
- Hasil AI dengan confidence rendah harus masuk review queue.
- Semua hasil harus menyimpan model dan waktu analisis.

Gunakan prompt Ollama yang meminta output JSON, lalu validasi JSON secara ketat.

Jika response tidak valid, lakukan maksimal satu repair attempt. Jika tetap gagal, simpan status `ANALYSIS_FAILED`.

### 9. Pencocokan gambar

Untuk MVP, implementasikan:

- SHA-256 untuk file identik.
- Perceptual hash untuk gambar yang di-resize atau dikompresi.
- Hamming distance threshold yang configurable.
- Reference image per subject.
- Penyimpanan hash, bukan hanya file mentah.

Buat interface agar face embedding dapat ditambahkan pada fase selanjutnya:

```go
type ImageMatcher interface {
    Compare(ctx context.Context, reference, candidate ImageInput) (MatchResult, error)
}
```

Jangan mengklaim perceptual hash sebagai face recognition.

Jika belum ada face recognition, tampilkan dengan jelas pada README dan dashboard bahwa fitur MVP hanya mendeteksi kemiripan gambar, bukan memastikan identitas wajah.

### 15. Security

Implementasikan:

- Bind dashboard ke `127.0.0.1` secara default.
- Optional local API token.
- Redaction untuk log.
- File permission ketat untuk profile browser dan SQLite.
- Domain allowlist.
- Action allowlist.
- Audit log append-only secara aplikasi.
- Content Security Policy untuk dashboard.
- Secure headers.
- Request body limit.
- Rate limit untuk local API.
